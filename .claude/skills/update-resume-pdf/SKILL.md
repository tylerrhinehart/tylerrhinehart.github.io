# Update the resume PDF

`index.html` is the source of truth. The PDF is a print of that page and must be
regenerated by hand whenever the HTML changes, or the "View PDF" link serves stale
content.

The page links to its own PDF, so the link has to be commented out before printing —
otherwise the button appears baked into the PDF, where it is dead weight.

## Steps

### 1. Comment out the View PDF button

In `index.html`, wrap the link in an HTML comment:

```html
<!-- <h3><a id="pdf" href="TylerRhinehart-Resume.pdf">View PDF</a></h3> -->
```

### 2. Serve the page locally

```bash
python3 -m http.server 8000
```

Run it in the background. Printing from a `file://` URL can drop the stylesheets;
serve over HTTP instead.

### 3. Print to PDF with headless Chrome

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --no-pdf-header-footer \
  --user-data-dir=<scratch>/chrome-profile \
  --print-to-pdf=<scratch>/resume-new.pdf \
  http://localhost:8000/index.html
```

`--no-pdf-header-footer` suppresses the date/URL furniture Chrome adds by default.
`--user-data-dir` pointed at a scratch directory keeps this run from touching the
user's real Chrome profile.

**Chrome often writes the PDF and then fails to exit.** Do not treat the hang as a
failure — check for the output file first, then clean up the process. Kill it by the
scratch profile path, never by process name, or you will take down the user's browser:

```bash
pkill -f "<scratch>/chrome-profile"
```

### 4. Back up the existing PDF

```bash
git mv TylerRhinehart-Resume.pdf TylerRhinehart-Resume.pdf.bak
```

Use `git mv` so the rename is tracked rather than showing up as a delete plus an add.

### 5. Install the new PDF under the expected name

The filename must match the `href` in the button exactly — `TylerRhinehart-Resume.pdf`.

```bash
cp <scratch>/resume-new.pdf TylerRhinehart-Resume.pdf
```

### 6. Restore the button

Uncomment the `<h3>` from step 1. Verify it is back before committing; shipping the
resume with its own download link commented out is the easy mistake here.

### 7. Verify, then commit

Commit the new PDF and the `.bak` together, along with the `index.html` changes.

## Verifying the output

The Browser pane downloads PDFs instead of rendering them, and naive text extraction
fails against Chrome's subsetted fonts — a script reporting "no text found" is an
extraction limitation, not proof the PDF is empty. Render it instead:

```bash
qlmanage -t -s 1200 -o <scratch>/ql TylerRhinehart-Resume.pdf
```

That writes a PNG of page 1 (macOS built-in, nothing to install). Read the image and
confirm:

- the "View PDF" button is **absent**
- contact details are current
- recent experience entries are present
- the skills grid has not reflowed into an orphan column

Page count sanity check:

```bash
python3 -c "import re;d=open('TylerRhinehart-Resume.pdf','rb').read();print(len(re.findall(rb'/Type\s*/Page[^s]',d)))"
```

## Layout note

`resume.css` sets `.skill { width: 32% }`, a three-across row. `index.html` overrides
it to 48% in an inline `<style>` block so the four skill blocks form a 2x2 instead of
a row of three with one orphan underneath. If skills are added or removed, revisit
that override — an odd count looks wrong in either layout.
